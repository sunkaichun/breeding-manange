# 养殖智能管理一体化项目 6 周实施执行计划

## 1. 项目概述

本项目基于现有《技术方案.md》，将“金蝶 ERP 数据自动同步、飞书多维表格建模、自动预警、移动端巡查闭环”落成一套可执行的 6 周项目实施计划，并追加 AI Java 后端、飞书机器人长连接接入和知识库问答分析的扩展开发计划。

项目面向养殖企业管理者、技术场长、IT 负责人和一线巡查人员，目标是把现有人工 Excel 报表升级为飞书多维表格中的实时数据驾驶舱，并通过飞书消息和任务表完成异常发现、责任分派、处理反馈和闭环追踪。

### 1.1 核心目标

1. 将现有人工 Excel 报表升级为自动化数据管理体系。
2. 打通金蝶 ERP 与飞书多维表格，实现批次、称重、领料等核心数据自动同步。
3. 建立养殖核心指标监控能力，包括体重异常、均匀度、料肉比、上市准确率、三对标、现场巡查。
4. 通过飞书消息和任务表实现异常预警、责任分派、处理反馈、闭环追踪。
5. 支持管理层、场长、技术员、巡查员在 PC 和移动端查看数据与处理任务。
6. 通过 LangGraph4j Java AI 后端支持自然语言查询、AI 分析任务、知识库问答和飞书机器人长连接触发。

### 1.2 实施范围

本次 6 周计划纳入：

- 飞书多维表格基础数据模型建设。
- 金蝶 ERP 数据同步方案落地。
- 基础公式、字段、视图、权限配置。
- 体重异常、均匀度、料肉比、上市预测等自动化规则配置。
- 移动端巡查入口与任务闭环。
- 试点场运行、培训、反馈优化、正式推广准备。
- AI Java 后端的模块拆分、任务编排、飞书 Base 查询、知识库接入和机器人长连接接入设计。

本次暂不纳入：

- 自研完整 App。
- 自研深度 AI 预测模型训练。
- 复杂成本核算系统。
- 金蝶 ERP 内部流程改造。
- 多区域大规模历史数据治理。

这些内容可作为二期或专项优化处理。

## 2. 实施原则

1. 先试点后推广：优先选择 1-2 个数据质量较好、业务配合度较高的养殖场试点。
2. 先数据准确再做复杂预警：字段口径、同步稳定性和计算准确性优先于高级图表和复杂模型。
3. 先核心闭环再高级指标：先跑通“数据同步 -> 异常识别 -> 消息通知 -> 任务闭环”，再扩展料肉比、三对标、上市预测等能力。
4. 飞书 Base 作为项目期统一工作台：项目问题、业务配置、异常处理和验收结果均围绕飞书多维表格沉淀。

## 6. AI Java 后端与飞书机器人长连接开发计划

本阶段用于承接“AI 分析案例、自然语言查询多维表格、开源知识库接入、飞书多维表格应用模式前端、数据可视化联动、飞书机器人消息触发”等扩展需求。它应建立在核心 Base 表结构和数据同步稳定之后，采用小任务拆分，确保每一步都能独立测试。

### 6.1 技术架构

推荐技术组合：

- 后端框架：Spring Boot。
- AI 编排：LangGraph4j。
- LLM/RAG 适配：LangChain4j 或自定义模型网关。
- 数据入口：飞书多维表格 OpenAPI、金蝶同步后的业务表、开源知识库。
- 前端入口：飞书多维表格应用模式页面、仪表盘、机器人会话。
- 机器人事件入口：飞书长连接消息事件消费，不使用事件回调地址。

后端模块建议：

| 模块 | 职责 | 可单步测试点 |
| --- | --- | --- |
| `ai-graph-runtime` | 定义 LangGraph4j 分析任务图、节点、状态流转 | 给定模拟输入可跑通完整图 |
| `lark-base-client` | 封装 Base 表、字段、记录查询和写回 | 能读取指定批次、写入分析结果 |
| `lark-im-client` | 封装飞书消息发送、卡片回复、任务通知 | 能向指定会话发送文本和卡片 |
| `lark-bot-long-connection-adapter` | 通过长连接消费机器人消息事件 | 能收到 `im.message.receive_v1` 并转成内部事件 |
| `analysis-domain` | 实现体重、均匀度、料肉比、上市预测等规则分析 | 单个批次样例可输出风险判断 |
| `rag-knowledge` | 接入开源知识库、养殖标准文档、操作规程 | 给定问题可返回引用片段 |
| `visualization-service` | 生成图表数据集并写回 Base 可视化表 | 查询结果可生成趋势图数据 |
| `task-orchestrator` | 管理 AI 任务、异步执行、状态追踪和失败重试 | 任务从待处理到完成状态可追踪 |
| `auth-security` | 做用户、角色、批次权限和数据范围校验 | 非授权用户无法查询无权限批次 |

### 6.2 机器人长连接处理链路

飞书机器人接入必须采用长连接方式，不采用事件回调机制。

```text
飞书用户给机器人发消息
  -> 飞书长连接消息事件
  -> BotLongConnectionConsumer
  -> BotMessageNormalizer
  -> MessageIdempotencyService
  -> CommandRouter
  -> AnalysisGraphService
  -> BaseQueryService / RagKnowledgeService / VisualizationService
  -> 飞书消息回复 + Base 结果写回
```

关键约束：

1. 只保留长连接消费者，不设计公网 HTTP callback、回调地址配置和回调签名校验流程。
2. 消费事件优先使用 `im.message.receive_v1`，上线前必须先确认事件 schema 和字段路径。
3. 文本消息的 `content` 按纯文本处理；交互卡片消息再按结构化 JSON 解析。
4. 每条消息按 `event_id`、`message_id` 或平台可用唯一键做幂等，避免断线重连或重复投递造成重复 AI 任务。
5. 生产环境同一机器人同一事件类型只允许一个 active consumer。多副本部署时通过 Redis、数据库锁或调度平台保证单实例消费。
6. 收到用户消息后先快速回复“任务已受理”，AI 分析异步执行，完成后再发送结果卡片。
7. 长连接消费者必须支持 ready 状态、健康检查、断线重连、指数退避、优雅停止和运行日志。

### 6.3 AI 相关 Base 表扩展

## 8. 验收标准

项目验收分为 8 类：

| 验收维度 | 验收标准 |
| --- | --- |
| 数据同步 | 批次基础信息、称重记录、领料记录可按计划同步；失败有提醒；关键字段可追溯来源 |
| 数据准确性 | 抽样批次与原 Excel/金蝶数据比对，核心字段和关键计算结果一致 |
| 指标计算 | 日龄阶段、目标体重、均重差异、达标状态、均匀度、FCR 等字段可自动计算 |
| 预警闭环 | 体重异常、均匀度异常至少两个核心场景能自动推送消息并创建任务 |
| 移动端使用 | 场长、技术员、巡查员可在手机端查看负责批次、接收预警、处理任务并回填结果 |
| AI 分析 | AI 后端可基于 Base 数据输出体重、均匀度、料肉比、知识库问答和建议动作 |
| 机器人长连接 | 用户给飞书机器人发消息后，可通过长连接触发 AI 任务，并收到受理和结果回复 |
| 培训上线 | 试点用户完成培训，能独立完成核心操作；上线切换责任人与支持机制明确 |

## 9. 风险与应对

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 金蝶接口字段与业务报表字段不一致 | 数据无法直接映射，影响第 2-3 周进度 | 第 1 周做字段盘点会，建立“金蝶字段 -> 业务口径 -> Base 字段”三列表 |
| 金蝶接口限流或不稳定 | 同步延迟，预警不及时 | 采用增量同步、失败重试、失败消息告警；关键数据保留手工补录入口 |
| 称重数据缺失、0 值或异常值 | 错误触发预警或影响指标可信度 | 增加数据有效性规则，异常数据进入待确认视图，不直接参与预警 |
| 养殖标准表维护不完整 | 目标值匹配失败，计算字段为空 | 第 3 周前完成标准表冻结，缺失品种先用默认规则或标记“待维护” |
| 飞书自动化规则复杂度过高 | 后期难维护，出现重复消息或漏发 | 先上线体重、均匀度两个核心规则；高级规则第 5 周逐步开放 |
| 移动端权限配置错误 | 用户看到不该看的数据，或看不到任务 | 第 5 周做角色权限专项测试，按场区、批次负责人、任务责任人验证 |
| 机器人长连接重复消费 | 多副本同时消费导致重复 AI 任务和重复回复 | 使用单实例锁、消息幂等表、任务状态机，重复事件直接跳过 |
| 长连接断线或权限失效 | 机器人无法及时响应用户消息 | 增加健康检查、自动重连、指数退避、权限到期巡检和告警 |
| LLM 输出不稳定 | 分析结论不可控或难以复盘 | 规则分析优先，LLM 只做解释和总结；输出结构化 JSON 并落库审计 |
| 知识库内容过期 | AI 建议引用旧标准或旧流程 | 知识库文档索引表记录版本和启用状态，业务负责人定期审核 |
| 用户仍依赖 Excel | 上线后使用率不足 | 第 6 周保留短期并行期，但明确 Excel 停用日期和数据唯一来源 |
| 试点数据量过小 | 预警规则无法充分验证 | 试点选择 1-2 个数据较完整场区，并补充历史称重数据回放验证 |

## 10. 上线切换安排

第 6 周后建议采用渐进式切换：

1. 并行 1-2 周：Excel 与飞书 Base 同步运行，重点核对数据口径。
2. 冻结 Excel 新增字段：避免业务继续扩展旧表。
3. 指定飞书为主数据看板：项目例会、异常处理、巡查任务只认飞书数据。
4. 到期停用人工汇总版 Excel：保留导出能力，但不再手工维护主报表。
